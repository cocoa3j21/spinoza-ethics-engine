# 幾何学的哲学推論エンジン 形式意味論仕様書 (docs/semantics.md)

**版数**: 2.1 (v0.1 Standard Freeze: Diagnostic Monotone Semantics)  
**更新日**: 2026-10-21  
**準拠**: Python 3.14 標準ライブラリ準拠

---

## 1. 基本方針と動機

本システムは、17〜18世紀のヨーロッパ合理論（デカルト、スピノザ、ライプニッツ）および批判哲学（カント）における「公理・定義・定理」の幾何学的演繹構造を、計算機上で再現可能・検証可能に分析するための形式意味論（Formal Semantics）を提供する。

従来のナイーブな真理値伝播エンジンが抱えていた論理的欠陥（前件否定の誤謬、別証明の無視、批判区別の混同）を克服するとともに、第三次監査（攻撃由来の支持と撤回によるフィードバック分析）の結果を受け、**v0.1 の標準推論意味論を `diagnostic_monotone` として凍結**する。

---

## 2. 推論意味論のモード分類

本エンジンは、信頼性と再現性を最優先するため、推論モードを明確に3分類し、通常運用を標準モードに固定する。

| モード名 (`SemanticsMode`) | 位置づけ | 概要と特性 | 適用範囲 |
| :--- | :--- | :--- | :--- |
| **`diagnostic_monotone`** | **v0.1 標準モード** | 肯定・否定支持の完全単調蓄積、事前Undercut確定、前提遮断なし、事後Conflict診断専用。有限ステップでの最小不動点への収束が100%数学的に保証される。 | ベンチマーク、最小前提探索、公開UI |
| **`experimental`** | **実験モード** | 動的撤回・完全真理維持（Truth Maintenance）。状態シグネチャによる振動検出（`CYCLE_DETECTED`）を備え、未収束を正常解や `UNKNOWN` と偽装しない。 | 攻撃フィードバック・非単調推論の学術的研究 |
| **`legacy`** | **旧方式 (非推奨)** | 幽霊的正当化（前提消滅後も衝突由来の否定支持が残存）により擬似停止する旧仕様。 | 通常ベンチマークおよび探索から**完全除外** |

## 3. v0.1 標準意味論 (`diagnostic_monotone`) の厳密な仕様

### (1) 単調支持蓄積
* 肯定支持集合（`positive_supports`）および否定支持集合（`negative_supports`）は、独立した集合として単調に蓄積される。
* 推論の途中で既存の支持が削除・撤回されることは一切ない。
* 明示的な否定支持が追加された場合でも、既に成立した肯定支持が消えることはなく、双方の支持が存在する `CONFLICT` 状態へと単調に遷移する。

### (2) 推論規則の発火条件
* 各推論規則 $R = \langle rule\_id, \{L_1, \dots, L_k\}, C \rangle$ は、指定された前件リテラル $L_i$ の支持が存在する（`state.is_supported(L_i)`）こと**のみ**を発火条件とする。
* 反対支持の存在による前提遮断（前提が `CONFLICT` していることによる不発化）は行わない。

### (3) ConflictPair の診断専用化 (Diagnostic Only)
* `ConflictPair(L_a, L_b)` は、推論実行中には否定支持を生成・注入しない。
* 評価アルゴリズムが不動点に到達した後、事後診断（`diagnostic_conflicts`）として両リテラルが同時に支持されているかを検査し、レポートする。
* これにより、衝突定義の追加や登録順序が推論の不動点計算結果を変更することは一切ない。

### (4) UndercutDefeater の事前確定
* 批判リテラルによって推論規則を無効化する `UndercutDefeater` は、評価開始前の初期状態（公理・仮定・注入批判）に基づき確定する。
* 推論途中の動的発火による規則の途中無効化や途中撤回は行わない。

### (5) シナリオの独立再計算
* 知識ベース（`KnowledgeBase`）は完全不変（Immutable）であり、シナリオや前提の変更時は、常にクリーンな初期状態（`EvaluationState`）から独立して再計算を行う。
* シナリオの追加・撤回は、独立再計算によって完全に元の結果へと復帰する（可逆性の担保）。

### (6) 対象範囲の限定
* 本意味論が保証される対象範囲は、有限個の命題、リテラル、および推論規則に限定される。

## 4. 2ビット支持モデル (Two-Bit Support Model)

各命題 $p \in \mathcal{P}$ に対する評価状態は、肯定支持ビット $b_+ \in \{0, 1\}$ と否定支持ビット $b_- \in \{0, 1\}$ の直積空間として定義される：

$$\mathcal{S} = \{0, 1\}^2$$

| ビット表記 $(b_+, b_-)$ | 状態名 (`TruthStatus`) | 意味論的解釈 |
| :---: | :---: | :--- |
| **`00`** | **`UNKNOWN`** | 未証明・未支持。肯定の根拠も否定の根拠も存在しない。 |
| **`10`** | **`TRUE`** | 肯定支持のみ成立。有効な証明規則により根拠づけられている。 |
| **`01`** | **`FALSE`** | 否定支持のみ成立。有効な反論・否定規則により根拠づけられている。 |
| **`11`** | **`CONFLICT`** | 肯定と否定の双方が支持された状態（固有の矛盾・二律背反）。 |

* 全命題は常に上記の4つのいずれか**唯一つに排他的に分類**される。
* 前提不足によって推論規則が不発になった場合、肯定支持 $b_+$ は $0$ のままであり、否定支持 $b_-$ が自動的に $1$ になることは決してない（前件否定の誤謬の根絶）。

## 5. 理論的区別と学術的注意事項

### (1) 辺数偶奇と負辺数偶奇の峻別
* 「奇数長負閉路」という表現は混同を招きやすいため、本仕様では以下を明確に区別する：
  - **辺数（エッジ数 / path length）の偶奇**: 閉路を構成する辺の総数が奇数か偶数か。
  - **負辺数（攻撃・批判エッジ数 / negative edge count）の偶奇（パリティ）**: 閉路に含まれる負の依存（符号反転、批判、衝突）の個数が奇数か偶数か。
* 非単調推論における振動・非収束の本質は、辺数の偶奇ではなく、**「奇数個の負辺を持つ閉路（negative_edge_count % 2 == 1）」** である。

### (2) 総合DAG制約と層化（Stratification）条件の峻別
* 推論規則、批判、衝突を統合したグラフ全体が非巡回である「総合DAG制約」と、論理プログラミング等における「層化条件（Stratification）」は**同義ではない**。
* **層化条件**: 否定・攻撃を跨ぐ依存関係のみに順序階層（層）を課し、同一層内での正の推論規則の相互依存（正閉路）は許容する。
* **総合DAG制約**: 正負すべての依存関係において閉路を一切禁じる、層化条件よりもはるかに強い十分条件である。

### (3) Stable Extension の存在性に関する注意
* 奇数個の負辺を持つ閉路が存在する論証枠組みであっても、外部からの優勢な攻撃（未反論の攻撃者による閉路内ノードの確定的な敗北）が存在する場合など、Dung の **Stable Extension（安定拡大）が存在し得る**。
* したがって、「奇数攻撃閉路が存在する $\implies$ Stable Extension 不存在」と断定することは理論的に誤りであり、本エンジンでは断定を行わない。

### (4) 独自撤回方式と Dung 抽象論証意味論の非対応性
* 本エンジンの実験モード（EXPERIMENTAL）等で実装された真理維持機構（Truth Maintenance / 動的撤回）と、Dung (1995) の抽象論証意味論（Grounded / Preferred / Complete / Stable extension 等）との厳密な数学的対応関係は**「未定義（Undefined）」**である。
* 本エンジンの撤回挙動を Dung の特定の拡大（Extension）概念と同一視してはならない。

### (5) アルゴリズムの停止状態と正当化検証結果の区別
* **停止状態（`state.status == CONVERGED`）**: ワークリストアルゴリズムが反復を終え、有限ステップで不動点に達した計算上のステータス。
* **正当化の十全性（`state.justification_validation`）**: 停止時点で蓄積された支持が、現在有効な前提と無効化されていない規則によって十全に根拠づけられているかの事後検証結果（幽霊的正当化 `phantom_supports` の有無）。
* 計算が停止したことと、得られた支持が十全に正当化されていることは別個の概念として区別して記録・報告される。
